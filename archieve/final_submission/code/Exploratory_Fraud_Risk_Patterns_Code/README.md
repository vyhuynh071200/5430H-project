# AMOD 5430 Fraud Visualization Project — Code Submission

This ZIP contains the reproducible source code for the paper:

**Exploratory Visualization of Fraud Risk Patterns in Bank Transaction Data**

The primary source file is `Exploratory_Fraud_Risk_Patterns.Rmd`. It reads the
transaction data, prepares analysis variables, calculates the displayed
summaries and fraud rates, and generates all tables and figures during
rendering.

The supporting file `src/helper_functions.R` contains reusable
data-preparation and plotting functions sourced by the R Markdown document.
Both files are required to reproduce the analysis.

No manually prepared screenshots are used as analytical results.

## Figures generated by the report

The report generates seven figures using either the full one-million-row
dataset or the balanced 2,000-row sample, depending on the analytical purpose.

| Figure | Analysis | Data source |
|---|---|---|
| Figure 1 | Class distribution of fraud and non-fraud transactions | Full dataset |
| Figure 2 | Transaction-type composition by fraud-group membership | Balanced sample |
| Figure 3 | Fraud rates across selected binary transaction characteristics | Full dataset |
| Figure 4 | Account-balance distributions by fraud group | Balanced sample |
| Figure 5 | Fraud rates by failed attempts and transaction type | Full dataset |
| Figure 6 | Hourly fraud rates by transaction type and merchant category | Full dataset |
| Figure 7 | Fraud rates and transaction shares by combined indicator count | Full dataset |

Therefore:

- Figures 1, 3, 5, 6, and 7 use the full dataset.
- Figures 2 and 4 use the balanced sample.

The full dataset is used when the figure reports transaction counts, fraud
rates, confidence intervals, or contextual comparisons intended to describe
the complete synthetic dataset.

The balanced sample is used only for sample-composition and distributional
comparisons where equal fraud and non-fraud group sizes improve visual
comparison. Percentages calculated from the balanced sample must not be
interpreted as population fraud prevalence.

Figure 7 uses an unweighted count of four selected transaction indicators:
international status, nighttime activity, recent PIN change, and two or more
failed attempts. This count is a descriptive synthesis of the EDA findings and
is not a validated predictive fraud-risk score.

## Data-selection behaviour

The R Markdown document first checks for:

```text
data/transactions.csv
```

If this file is available, the full dataset is used for:

- population transaction counts;
- fraud-rate estimates;
- confidence intervals;
- failed-attempt comparisons;
- hourly and merchant-category comparisons;
- combined-indicator summaries.

The balanced sample is used only for selected distributional and
sample-composition figures.

If the full dataset is unavailable, the included sample can be used to
demonstrate that the code executes. However, sample-mode output does not
reproduce the full-data numerical results reported in the paper.

To reproduce the published results, place the original dataset at:

```text
data/transactions.csv
```

Do not modify the source dataset.

## Figure layout

The paper uses the IEEE two-column format.

Single-column figures are used where labels remain readable. Wide figures,
including the failed-attempt comparison, merchant-and-time analysis, and
combined-indicator summary, use the two-column `figure*` environment.

LaTeX may place wide figures at the top of the next available page. This is
normal IEEE float behaviour.

## Interpretation notes

The analysis is exploratory and descriptive.

The figures identify visible associations but do not establish:

- causation;
- predictive performance;
- validated decision thresholds;
- real-world banking behaviour.

The dataset is synthetic. The combined indicator count is an unweighted
descriptive summary and should not be interpreted as a validated fraud-risk
score.
